# Дополнительные площадки: Хабр Карьера, SuperJob, getmatch, «Работа России», Rabota.ru

Цель: подписки и подборка `/catalog` собирают вакансии со всех площадок, а не только с hh.ru.
Уведомления, стоп-слова, скрытые компании, трекер изменений и подборка работают одинаково
для всех площадок. Вакансия, опубликованная сразу на нескольких площадках, приходит один раз.

Документ — план к этапу 13 из [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).
Все цифры и параметры ниже проверены запросами 2026-10-28 (с Mac через немецкий VPN),
кроме помеченных «по документации».

## 2. Общий конвейер — одинаковый для всех площадок

```
cron площадки ──► для каждой активной подписки, где площадка включена:
   1. адаптер переводит SearchFilters в параметры площадки        (раздел 2.2)
   2. запрос(ы) к площадке с её RateLimiter и ретраями            (app/sources/http.py)
   3. ответ → VacancyShort (id с префиксом площадки, компания, зарплата, город, дата)
   4. локальные фильтры: то, что площадка не умеет + стоп-слова + скрытые компании
   5. upsert в vacancies, связь с подпиской (subscription_matches)
   6. проверка дубля с другими площадками (раздел 2.4)
   7. не дубль и новая → событие NEW → уведомление (notifier как сейчас)
```

Подборка (`sync_catalog`) идёт так же, но через `search_all` и без шага 7.

### 2.1. Площадка ≠ способ получения

Сейчас `SourceName` (`api`, `rss`, `parser`) описывает способ получения с hh.ru. Добавляется
второе измерение — **площадка** `Portal`: `hh`, `habr`, `superjob`, `getmatch`, `trudvsem`, `rabota`.

```
app/sources/
  base.py      SearchFilters, VacancySource, FullSearchSource (+ поле portal)
  http.py      RetryingClient — общий
  hh/          переезжают hh_api.py, hh_rss.py, hh_search_page.py, site.py, fallback.py, details.py
  habr/        rss.py, page.py, details.py, filters.py
  superjob/    api.py, details.py, filters.py
  getmatch/    feed.py
  trudvsem/    api.py
  registry.py  Portal → адаптер; включены только площадки с настройками (ключ, флаг)
```

**Идентификатор.** Вакансии hh.ru сохраняют прежний id, чтобы не трогать внешние ключи пяти
таблиц. У остальных — префикс через дефис: `habr-1000168870`, `sj-51234567`, `gm-36738`,
`td-1a0e3e18aa9711f0b9afbdc82d0d5dcd` (uuid без дефисов). Не двоеточие: оно разделяет поля
в `callback_data` кнопок Telegram. Колонка `vacancies.id` расширена с 32 до 48 символов,
добавлена `vacancies.portal` (по умолчанию `hh`). Кнопка подборки с самым длинным id
занимает ~47 байт из 64 (`app/sources/portals.py`).

**Окно поиска — у каждой площадки своё.** `last_checked_at` и `catalog_synced_at`
переехали из `subscriptions` в таблицу `subscription_portal_states`
(подписка × площадка). Новая площадка при первой проверке подгружает свои 24 часа, не трогая
остальные; упавшая площадка не сдвигает своё окно. Подборка сравнивает «была в последней
выдаче» с синхронизацией площадки этой вакансии.

### 2.2. Ключевые слова: одно описание — свой запрос для каждой площадки

Подписки хранят ключевые слова на языке hh.ru: `NAME:(frontend OR react OR …)` — так их
задают пресеты и бот (`parse_keywords`). Другие площадки так не умеют, поэтому адаптер
разбирает запрос в список слов и признак «искать в названии» (общий помощник появится в
13.2). Новое поле в фильтрах не нужно, и отредактированные в боте слова тоже работают.

- hh.ru получает запрос как есть.
- SuperJob передаёт весь список одним запросом: поиск по названию, «любое из слов».
- Хабр и «Работа России» не умеют «или», поэтому по одному запросу на слово, результаты
  объединяются. Синонимы (`reactjs`, `front-end`) пропускаем: поиск их и так находит.
- getmatch фильтрует у нас.
- В конце всегда проверяем, что слово есть **в названии**. Поиск площадок полнотекстовый,
  и без проверки в выдачу попадут, например, тестировщики, у которых в описании упомянут React.

Обычная подписка со свободным текстом (`text`) передаёт текст как есть, без проверки названия.

### 2.3. Перевод фильтров

| Фильтр | hh.ru | Хабр | SuperJob | getmatch | Работа России |
|---|---|---|---|---|---|
| Вся Россия | `area=113` | без города | без `town` | локально, формат `remote` | без региона |
| Казань | `area=88` | `city_id=698` | `town=55` | локально, город «Казань» | `/region/1600000000000` (Татарстан), город локально |
| Удалёнка | `REMOTE` | `remote=true` | `place_of_work=2` | `format: remote` | локально по графику/тексту |
| Офис / гибрид | `ON_SITE`, `HYBRID` | без `remote` + город | `place_of_work=1` (гибрида нет) | `office` / `hybrid` | локально |
| Опыт | `experience` | `qid`: 1 стажёр, 3 junior, 4 middle, 5 senior, 6 lead | `experience`: 1 без опыта, 2 от 1 г., 3 от 3 л., 4 от 6 л. | локально | — |
| IT-роли | `professional_role` | `s[]`: 3 фронтенд, 4 фулстек | `catalogues=33` (IT) | вся лента — IT | — |
| Зарплата от | `salary` | `salary` | `payment_from` | локально | локально |
| Свежие | `date_from` | `sort=date` | `date_published_from` (unix) | локально по `published_at` | `modifiedFrom` |

Переводы опыта неточные. hh «1–3 года» ≈ Хабр junior + middle ≈ SuperJob `2`. Подборки
опыт не ограничивают, поэтому неточность важна только для обычных подписок. Для них берём
диапазон пошире, а лишнее не отсекаем: лучше показать вакансию, чем потерять.

### 2.4. Дубли между площадками

Ключ дубля: `employer_key(компания)` (уже есть, общий для всех источников) +
нормализованное название (нижний регистр, без грейдов senior/middle/junior, скобок и
знаков) + город (для удалёнки — «remote»). Окно — 14 дней.

- В `vacancies.duplicate_of` записывается первая увиденная вакансия группы.
- Уведомление приходит только о первой. Позже найденный дубль ничего не шлёт.
- В подборке одна карточка с кнопками «Открыть на hh.ru», «Открыть на Хабре».
  Отметка «✅ Откликнулся» ставится на всю группу.

### 2.5. Надёжность и нагрузка

- У каждой площадки своя cron-задача, свой `RateLimiter` и своя блокировка в Redis.
  Сломался Хабр — hh.ru продолжает работать.
- Сердцебиение и алерт админу (5 неудачных циклов подряд) — по каждой площадке отдельно.
- Страницы сайтов — не чаще раза в 2 секунды, понятный `User-Agent`, как сейчас для hh.ru.
- Включение площадки — переменными в `.env`: `PORTALS=hh,habr,superjob,getmatch,trudvsem`.
  SuperJob без `SUPERJOB_API_KEY` отключается сам.

## 3. Хабр Карьера

**Доступ:** без ключа. RSS и страницы отвечают 200.

### 3.1. Новые вакансии — RSS

```
GET https://career.habr.com/vacancies/rss?type=all&sort=date&q=react&remote=true
```

- Параметры: `q` (одно слово), `sort=date`, `remote=true`, `city_id=698`, `qid`, `s[]`,
  `salary`, `with_salary=true`.
- Отдаёт **не больше 50** записей, параметр `page` не работает. Если все 50 новее даты
  последней проверки, окно «переполнено» — добираем страницей поиска (как у hh.ru).
- Поля: `guid` = id, `link`, `title` в виде «Требуется «…» (город)», `author` = компания,
  `pubDate`. В `description` текстом: города, «Можно удалённо», навыки. Зарплаты и id
  компании в ленте нет. Это нормально: уведомление строится по ленте, а детали дотягивает трекер.
- Частота: раз в 2 минуты, по запросу на каждое ключевое слово (4–5 запросов на подписку).

### 3.2. Полная выдача — страница поиска

```
GET https://career.habr.com/vacancies?type=all&sort=date&q=frontend&page=2
```

- В HTML есть `<script type="application/json" data-ssr-state="true">`.
  В нём `vacancies.list` (25 штук) и `vacancies.meta` (`totalResults`, `totalPages`).
- Поля вакансии: `id`, `href`, `title`, `company` (`id`, `title`), `salary`
  (`from`, `to`, `currency`), `remoteWork`, `locations[].title`, `qualification`,
  `employment`, `publishedDate.date`, `archived`.
- Сколько выходит: `frontend` 32, `фронтенд` 32, `react` 46, `vue` 15, `angular` 8,
  специализации `s[]=3` (фронтенд) 10, `s[]=4` (фулстек) 17. Без повторов — **72 вакансии**.
  Вся выдача по Хабру — около 20 запросов раз в 2 часа.

### 3.3. Трекер

`GET /vacancies/{id}` — в `data-ssr-state` объект `vacancy` с `archived` и `salary`.
Удалённая вакансия отдаёт 404.

### 3.4. Что получилось на деле (2026-10-29)

- Поиск Хабра полнотекстовый и очень широкий: по «react» и «frontend» приходят Java-, Go- и
  QA-вакансии, где слово есть только в описании. Из ~70 найденных по словам в названии
  фронтенд есть у 12 удалённых — их и берём (так же, как `NAME:` на hh.ru).
- Квалификацию (Middle, Senior…) указывают не везде. Вакансии без неё фильтр опыта не
  отбрасывает.
- Подписки только с ролями без ключевых слов («Техподдержка», «IT в целом») на Хабре не
  ищутся: соответствия ролям hh.ru там нет.
- Зарплата в RSS только текстом в заголовке; полную (и id компании) даёт страница поиска.
  «Скрыть компанию» работает по ключу из названия, поэтому одинаково для RSS и страниц.
- Запросов: 7 слов × подписку раз в 2 минуты, не чаще раза в 2 секунды. Полная выдача
  для подборки — ~15 секунд.

### 3.5. Тесты

Фикстуры — настоящие ответы: `habr_rss.xml`, `habr_search_page.html`, `habr_vacancy.html`.

## 4. SuperJob

**Доступ:** официальный API `https://api.superjob.ru/2.0/`. В каждом запросе заголовок
`X-Api-App-Id: <ключ>`. Без ключа — 403 «Необходимо передать ключ приложения».
Справочники (`/catalogues/`, `/towns/`) отвечают и без ключа.
Лимит по документации: 120 запросов в минуту с одного IP.

**Что сделать тебе:** зарегистрировать приложение на https://api.superjob.ru/register/
(бесплатно) и вписать ключ в `.env` как `SUPERJOB_API_KEY`. Публично ключ не выкладывать.

### 4.1. Поиск — новые и полная выдача одним методом

```
GET /2.0/vacancies/?keywords[0][srws]=1&keywords[0][skwc]=or
    &keywords[0][keys]=frontend фронтенд react vue angular next.js
    &place_of_work=2&order_field=date&order_direction=desc
    &date_published_from=<unix>&count=100&page=0
```

- `keywords`: `srws=1` — искать в названии, `skwc=or` — любое из слов. Один запрос вместо
  пяти (по документации).
- Город: `town=55` (Казань, проверено через `/towns/?keyword=Казань`); без `town` — вся Россия.
- `place_of_work`: 1 — офис, 2 — удалённо, 3 — разъездной. Гибрида нет.
- `experience` 1–4, `payment_from`, `no_agreement=1` (только с зарплатой),
  `catalogues=33` (IT, Интернет, связь), подкаталоги: 48 «Разработка, программирование»,
  36 «Web-верстка», 42 «Создание сайтов», 604 «Мобильная разработка».
- Не больше 100 на страницу и **500 на запрос**. Для новых вакансий хватит одной страницы,
  для подборки — до 5.
- Ответ: `objects`, `total`, `more`. Поля: `id`, `profession`, `firm_name`, `id_client`,
  `town.title`, `payment_from`, `payment_to`, `currency`, `date_published` (unix),
  `link`, `is_archive`, `place_of_work`, `experience`.
- `payment_from = 0` значит «не указана» — сохраняем как `None`.

### 4.2. Трекер

`GET /2.0/vacancies/{id}/` → `is_archive`, `is_storage` (удалена), зарплата.

### 4.3. Проверка

Количество по Frontend совпадает с сайтом SuperJob. Названия параметров `keywords` сверим
на живом ключе.

## 5. getmatch

**Доступ:** внутренний JSON-API сайта без ключа. Это IT-площадка с вакансиями от
рекрутеров, почти везде указана зарплата.

```
GET https://getmatch.ru/api/offers?offset=0&limit=100
```

- Всего **~914 вакансий** по всем IT-специальностям. Параметры `q` и `sp` сервер
  **не применяет**, лента отсортирована не по дате. Поэтому забираем ленту целиком:
  10 запросов раз в 15 минут.
- Фильтрация у нас: слово в `position`; формат и город из
  `location_requirements[].format` (`remote`, `hybrid`, `office`) и `.city`;
  `published_at` для «свежих».
- Поля: `id`, `position`, `company.name` (id компании нет → скрываем по названию, это уже
  работает), `salary_display_from/to`, `salary_currency`, `salary_hidden`, `url`
  (относительный, приклеиваем `https://getmatch.ru`), `is_active`.
- Трекер бесплатный: лента и так приходит целиком. Если вакансии нет в ленте, она закрыта.
  Вакансия может пропасть из-за сбоя ответа, поэтому закрытой её считаем после двух
  пропусков подряд.

## 6. Работа России (trudvsem.ru)

**Доступ:** открытые данные Роструда, без ключа.

```
GET http://opendata.trudvsem.ru/api/v1/vacancies?text=frontend&modifiedFrom=2026-10-27T00:00:00Z&offset=0&limit=100
GET http://opendata.trudvsem.ru/api/v1/vacancies/region/1600000000000?text=frontend   (Татарстан)
```

- `offset` — **номер страницы**, а не сдвиг; `limit` до 100.
- Поиск по тексту очень неточный: по `frontend` в Татарстане приходят тестировщики,
  поэтому обязательна проверка слова в названии (`job-name`).
- По `frontend` по всей России — 30 вакансий, по `react` — 39. Площадка в основном про
  госкомпании и бюджет, IT мало. Подключаем последней, опрос раз в 30 минут.
- Поля: `id` (uuid), `job-name`, `company.name`, `company.inn`, `salary_min`, `salary_max`,
  `region.name`, `schedule`, `vac_url`, `creation-date`, `date_modify`.
- Трекер: вакансия пропала из выдачи → закрыта.

## 7. Rabota.ru

С Mac и сайт, и `api.rabota.ru` отвечают 403, скорее всего из-за зарубежного IP.

**Что сделать тебе (завтра, на домашнем ПК без VPN):**

```
curl.exe -s -o NUL -w "%{http_code}" "https://www.rabota.ru/vacancy/?query=frontend"
```

- `200` — изучу страницу и опишу способ, как для Хабра.
- `403` — площадку не берём.

## 8. Авито Работа — не берём

Сайт отвечает 429 (защита от ботов). API Авито открыт только работодателям для их
собственных вакансий. Обход защиты нарушает правила и ведёт к блокировке IP.

## 10. Риски

| Риск | Что делаем |
|---|---|
| Хабр или getmatch поменяют разметку или JSON | Тесты на фикстурах покажут, что сломалось; алерт админу; остальные площадки работают |
| SuperJob ограничит число запросов | Один запрос на подписку раз в 2 минуты — далеко от 120/мин |
| Ложные дубли (одна компания, похожие вакансии в разных городах) | Город в ключе дубля; при сомнении шлём оба |
| Площадка недоступна с зарубежного IP | Домашний ПК без VPN |
| Автоотклики | Только hh.ru через официальный API (этап 8b). На других площадках откликаемся вручную по кнопке «Открыть» |
