# Часть 2. Автоотклики: анализ вакансии, сопроводительное письмо, уведомления

Задача из [search-job.md](search-job.md): бот сам находит подходящие вакансии на всех площадках,
пишет под каждую своё письмо и откликается. Если работодатель просит тестовое или ответить на
вопросы, бот присылает уведомление. Цель: больше откликов, больше собеседований, оффер.

Документ отвечает на вопрос «сможем ли» и описывает, как делаем. Код пока не пишем.

## 1. Короткий ответ: сможем, но не на всех площадках одинаково

| Что | Можно? | Как |
|---|---|---|
| Поиск вакансий на всех площадках | ✅ уже работает | часть 1: hh, Хабр, SuperJob, getmatch, «Работа России» |
| Анализ вакансии (подходит ли, какая роль, что просят в письме) | ✅ | LLM (Claude API) по полному описанию вакансии |
| Уникальное письмо под вакансию | ✅ | LLM + проверка текста кодом (раздел 5) |
| Автоотклик на hh.ru | ⚠️ да, с риском | **только через браузер** с твоим аккаунтом (раздел 2) |
| Автоотклик на SuperJob | ⚠️ проверить | у API был метод отклика с OAuth соискателя; если закрыт, то браузер |
| Автоотклик на Хабр Карьере, getmatch | ⚠️ | браузер; часть вакансий Хабра ведёт на сайт компании или на hh |
| «Работа России» | ❌ | вход через Госуслуги, автоматизировать не будем, только уведомление |
| Вакансии с откликом на сайте компании | ❌ | только уведомление со ссылкой и готовым письмом |
| Уведомления: тестовое, вопросы, приглашение, отказ, сообщение | ✅ | бот читает раздел откликов и чаты, пишет в Telegram |
| Ответы на вопросы работодателя при отклике | ⚠️ | LLM готовит ответы, ты подтверждаешь в Telegram |
| Выполнение тестовых заданий | ❌ не автоматизируем | уведомление + дедлайн; это твоя работа, и она решает исход |

Итог: автоматизировать можно примерно 70–80% рутины (поиск, отбор, письма, отклики на hh и
крупных площадках, слежение за ответами). Тестовые, собеседования и сложные вопросы остаются
на тебе, бот только не даёт их пропустить.

## 2. Главный риск: hh.ru закрыл API для соискателей

С 15 декабря 2025 hh.ru закрыл ту часть API, через которую сторонние приложения действовали от
имени соискателя: отклики (`/negotiations`), резюме. Поэтому заявка на dev.hh.ru (#31784) для
откликов уже не поможет: даже одобренное приложение откликаться не сможет.

Что продолжает работать у сервисов автооткликов: вход в аккаунт по коду из SMS/почты и отклик
**так же, как это делает человек на сайте**. Значит, наш путь:

- **Playwright** (управляемый Chrome) с постоянным профилем браузера на домашнем компьютере.
- Первый вход делаешь ты сам в открытом окне (номер + код из SMS). Дальше бот живёт на cookies.
  Когда hh попросит войти заново, бот присылает в Telegram «нужен вход» и ждёт.
- Отклик: открыть вакансию → «Откликнуться» → выбрать нужное резюме → вставить письмо →
  ответить на вопросы, если они есть → отправить → сохранить результат.

**Не делаем:** не подделываем ключи мобильного приложения hh, не обходим капчу сервисами
распознавания, не создаём несколько аккаунтов. Это прямой путь к блокировке единственного
аккаунта с резюме.

**Риски и как их снижаем:**

| Риск | Что делаем |
|---|---|
| hh считает это нарушением правил и блокирует отклики или аккаунт | лимит ниже человеческого: до 40–50 откликов в день (у hh лимит до 200 в сутки), паузы 1–5 минут со случайным разбросом, только 9:00–21:00 |
| одинаковые массовые отклики (именно их hh и пытается остановить) | у каждой вакансии своё письмо; не откликаемся на всё подряд, только с оценкой соответствия выше порога |
| капча или повторный вход | бот останавливает очередь и пишет в Telegram, ты решаешь вручную |
| hh меняет вёрстку, и кнопки «ломаются» | селекторы в одном файле, тест на сохранённых страницах, алерт админу при 3 ошибках подряд |
| отклик ушёл на неподходящую вакансию | первую неделю полуавтомат: всё через подтверждение в Telegram (раздел 4) |

Важно понимать: полностью безопасного автоотклика на hh в 2026 году нет. Решение, готов ли ты
рискнуть аккаунтом, за тобой (вопрос 1 в разделе 10). Безопасный вариант — режим «бот готовит,
ты нажимаешь»: бот присылает вакансию + письмо, кнопка открывает вакансию, письмо копируется
одним нажатием. Это уже в разы быстрее, чем сейчас, и с нулевым риском.

## 3. Конвейер

```
часть 1: новая вакансия (уже есть: fetcher → дедупликация → событие NEW)
   │
   ▼
1. полное описание вакансии (details-источник площадки, расширяем до текста описания)
2. быстрый отбор кодом: стоп-слова, скрытые компании, уже откликались, архивная
3. анализ LLM → JSON:
     роль: frontend | qa | support | analyst | other
     оценка соответствия 0–100 и 2–3 причины
     обязательное слово/фраза для письма («напишите в письме слово „банан“»)
     вопросы работодателя, тестовое, отклик на внешнем сайте
     за что зацепиться в письме: продукт, стек, задачи, ценности компании
4. решение:
     оценка < порога                → пропуск (видно в /stats)
     внешний сайт / «Работа России» → уведомление со ссылкой и письмом
     есть вопросы или тестовое      → в Telegram на подтверждение
     иначе                          → очередь откликов (или подтверждение в полуавтомате)
5. письмо: LLM по шаблону роли → проверка кодом (раздел 5) → при ошибке перегенерация, 2 попытки
6. очередь откликов (arq, отдельный воркер с лимитами): адаптер площадки отправляет отклик
7. запись в applications: вакансия, резюме, текст письма, статус, время
8. трекер откликов раз в 30–60 минут: приглашение / отказ / тестовое / новое сообщение → Telegram
```

Шаги 1–2 и всё до события NEW уже есть в части 1. Новое: анализ, письмо, очередь, адаптеры
отклика, трекер откликов.

## 4. Режимы работы

1. **Черновики** (старт, без риска): бот присылает карточку «вакансия + оценка + письмо» с кнопками
   «Откликнуться» / «Переписать» / «Пропустить». «Откликнуться» в этом режиме открывает
   вакансию, письмо копируется.
2. **Полуавтомат**: «Откликнуться» отправляет отклик через браузер. Нужно, чтобы проверить
   качество писем и адаптеры на реальных вакансиях.
3. **Автомат**: вакансии с оценкой выше порога (например 75) и без вопросов уходят сами, утром
   приходит сводка «вчера отправлено 34 отклика, вот список». Остальные через подтверждение.

Переключение режима и порога — команды бота, отдельно для каждой роли. Например, frontend в
автомате, а аналитик данных пока в черновиках.

## 5. Сопроводительное письмо

Требования из search-job.md переводим в правила, которые проверяет **код**, а не только промпт:

| Правило | Проверка |
|---|---|
| без смайликов | регулярка по диапазонам эмодзи |
| без длинных тире | `—` и `–` заменяем на запятую/дефис или отправляем на перегенерацию |
| не слишком длинное | 400–900 символов, 3–6 предложений; короткий вариант до 400 |
| обязательное слово из вакансии | если анализ нашёл слово, оно должно быть в тексте дословно |
| не похоже на AI | стоп-лист фраз: «я с большим энтузиазмом», «идеально подхожу», «в динамичной команде», «уверен, что смогу внести вклад», «рад(а) возможности»; без маркированных списков; без «Кроме того», «Более того» в начале фраз |
| не одинаковое | сравниваем с последними 20 письмами, при сходстве > 60% перегенерация |

Как письмо становится разным:

- **Шаблон по роли.** Для frontend — опыт и стек. Для QA — «как разработчик писал unit-тесты на
  Jest/RTL, понимаю, где ломается код». Для техподдержки — работа с заказчиком, разбор проблем.
  Для аналитика — работа с данными и требованиями. Основа — твоё резюме и `docs/COVER_LETTER.md`.
- **Крючок из вакансии.** Первая фраза про их продукт, задачу или стек, а не «меня заинтересовала
  вакансия». Если стек не совпадает (Vue вместо React), одна фраза о переходе.
- **Ответ на просьбу работодателя** (слово, вопрос «почему мы») — первой строкой.
- **Город/формат**: для офиса в Казани — «я в Казани, могу выйти быстро».
- **Никаких выдуманных фактов.** LLM получает только факты из резюме и пишет только о них. Это
  отдельное правило промпта: выдуманный опыт всплывёт на собеседовании.

**Модель и цена.** Выбрана локальная модель, бесплатно (раздел 10.2). Ниже расчёт для облачного
Claude, если позже понадобится. Анализ (шаг 3) — Claude Haiku 5.5: ~3 тыс. токенов на вход, ~$0,0003 за
вакансию. Письмо — Claude Opus 5.5 ($4 / $20 за 1 млн токенов): ~3 тыс. на вход и 400 на выход,
около $0,02 за письмо. 50 писем в день — примерно $30 в месяц, на Sonnet 5.5 ($2 / $10) вдвое
дешевле. Начнём с Opus и сравним качество с Sonnet на 20 вакансиях. Нужен ключ Anthropic API
(вопрос 4).

## 6. Резюме под каждую роль — без этого QA и аналитика не сработают

Отклик на вакансию тестировщика с резюме «Frontend-разработчик» работодатель почти всегда
отклоняет, даже с хорошим письмом: фильтры и HR смотрят на заголовок резюме. Поэтому на hh
нужно 3–4 резюме:

- Frontend-разработчик (основное)
- QA-инженер / тестировщик (упор на тесты, Jest, RTL, понимание кода)
- Специалист технической поддержки (L2) (упор на разбор проблем, работу с пользователями)
- Аналитик данных (если есть SQL, Excel, Python или хотя бы pet-проект с данными, иначе отклики будут пустыми)

Бот выбирает резюме по роли из анализа. Резюме тоже могу помочь составить из текущего CV.

## 7. Уведомления

| Событие | Откуда берём | Что делает бот |
|---|---|---|
| вопросы работодателя при отклике | форма отклика hh | LLM готовит ответы → Telegram с кнопками «Отправить» / «Изменить» |
| тестовое задание (до отклика или после) | описание вакансии, форма отклика, сообщения | уведомление со ссылкой, сроком и кратким описанием задания |
| приглашение на собеседование | раздел «Отклики» hh (статус «Приглашение») | срочное уведомление 🔔 + напоминание, если не ответил за 2 часа |
| сообщение от работодателя | чаты hh | текст сообщения + черновик ответа от LLM, отправка только после подтверждения |
| отказ | статус отклика | тихое уведомление, учёт в статистике |
| нужен повторный вход / капча | адаптер | остановка очереди + уведомление |

Читать раздел откликов и чаты через браузер проще, чем откликаться: это просто просмотр страниц
раз в 30–60 минут. Сложность средняя, не высокая.

На сообщения работодателей бот **сам не отвечает** никогда, только черновик. Ошибка в переписке
с живым человеком стоит дороже, чем 10 минут задержки.

## 10. Решения (ответы от 2026-11-06)

1. **Режим:** идём до полного автомата через браузер. Путь всё равно проходит через
   «черновики» и полуавтомат (раздел 4), чтобы проверить письма и адаптер до массовых откликов.
2. **Резюме:** создаём 4 резюме: frontend, QA, техподдержка, аналитик данных. Для аналитика
   упор на SQL и Excel плюс опыт работы с данными во frontend-проектах.
3. **Объём:** 30–50 откликов в день на hh.
4. **LLM:** локальная модель на домашнем компьютере (раздел 10.2). Сначала Mac (Intel i9, 32 ГБ),
   потом Windows (16 ГБ). ❓ осталось узнать видеокарту на Windows.
5. **Зарплата:** frontend от 160 000 ₽. QA, поддержка, аналитик без нижней границы: если
   зарплата не указана, откликаемся; если указана, решение по оценке соответствия, а через
   1–2 недели смотрим вилки в `/stats` и при необходимости ставим порог. Города и формат
   (Казань + удалёнка) одинаковые для всех ролей.
6. **Тон письма:** «Здравствуйте!» и подпись с Telegram, как в `docs/COVER_LETTER.md`.

### 10.1. Что за ключ и где его взять

Анализ вакансий и письма пишет не наш код, а языковая модель (как ChatGPT, только через
программу). Чтобы наш бот мог к ней обращаться, нужен **API-ключ**: строка вида `sk-...`, которая
лежит в `.env`. По ней сервис понимает, с чьего счёта списывать деньги за запросы. Платим за
использование: при 50 письмах в день это $15–30 в месяц.

Сложность в том, что Anthropic (Claude) и OpenAI не работают с Россией: не принимают российские
карты и блокируют запросы с российских IP. Варианты:

| Вариант | Оплата | Доступ из РФ | Качество писем на русском |
|---|---|---|---|
| **Anthropic API напрямую** (console.anthropic.com) | зарубежная карта | только через VPN/прокси на домашнем компьютере | лучшее |
| **Посредник** (OpenRouter и подобные) с моделями Claude | криптовалюта или посредники оплаты | обычно через VPN | то же, что Claude, плюс наценка |
| **YandexGPT / GigaChat** | российская карта, рубли | без VPN | хуже, чаще «канцелярский» текст, больше перегенераций |

Код пишем так, что модель меняется одной настройкой, поэтому начать можно с любого варианта.

### 10.2. Выбрано: локальная модель на домашнем компьютере

Модель запускается прямо на домашнем Windows-компьютере через **Ollama** (бесплатная программа,
ставится как обычное приложение). Без ключа, без оплаты, без VPN, тексты вакансий никуда не уходят.

- **Модели.** Открытые модели, которые нормально пишут по-русски: Qwen, Gemma и русские дообучения
  от T-Bank (T-Lite / T-Pro). Какую именно, выбираем после замера на 20–30 реальных вакансиях.
- **Железо.** Зависит от видеокарты:
  - видеокарта с 8 ГБ памяти: модель 7–9B, письмо за 10–30 секунд;
  - 12–16 ГБ и больше: модель 12–14B, письма заметно лучше;
  - без подходящей видеокарты: на процессоре, 1–3 минуты на письмо и нужно 16+ ГБ ОЗУ. При
    50 письмах в день это 1–2 часа фоновой работы, для очереди откликов это терпимо.
- **Качество.** Ниже, чем у Claude: чаще шаблонные фразы, ошибки в падежах, может «придумать»
  опыт. Поэтому важнее становятся проверки кодом из раздела 5, перегенерация и режим «черновики»
  на первой неделе. Анализ вакансии делаем проще: часть полей (зарплата, город, формат,
  обязательное слово по шаблонам «укажите в письме…») достаём кодом, модели остаётся роль,
  оценка и «крючок» для письма.
- **Код.** Ollama отдаёт тот же формат запросов, что и облачные модели, поэтому если позже
  появится ключ, переключение займёт одну настройку в `.env`.
- **Где работает.** Сначала Mac, потом проект клонируется на Windows и запускается там.

| | Mac (разработка и первый запуск) | Windows (постоянная работа) |
|---|---|---|
| Железо | Intel Core i9-8950HK (6 ядер), 32 ГБ ОЗУ | 16 ГБ ОЗУ, видеокарта ❓ |
| Чем считает модель | только процессор: Ollama на Intel Mac видеокарту Radeon не использует | NVIDIA, если она есть, иначе процессор |
| Модель | 7–9B в 4-битном сжатии, около 5 ГБ памяти; можно попробовать 12–14B (~9 ГБ) для сравнения | 7–9B: рядом работают Docker, Postgres, Redis и Chrome, на 14B памяти не хватит |
| Скорость письма | ~2–3 минуты (разбор вакансии ~1–2 мин + текст ~1 мин) | с NVIDIA 8+ ГБ 10–30 секунд, без неё как на Mac |

Что из этого следует:

- 50 писем в день на процессоре — это 2–3 часа фоновой работы. Для очереди, которая отправляет
  отклик раз в несколько минут, это нормально, но генерация идёт по одной, параллельно не ускорить.
- Промпт держим коротким: факты о тебе — компактный `profile.yaml` (~500 токенов), описание
  вакансии обрезаем до ~1500 токенов без «о компании» и списков льгот. На процессоре время разбора
  промпта почти равно времени генерации, поэтому короткий промпт сокращает время вдвое.
- Разбор вакансии и письмо делаем **одним запросом**, а не двумя: так промпт обрабатывается один раз.
- Ollama ставится на систему, не в Docker (на Windows так она видит видеокарту). Контейнеры
  обращаются к ней по адресу `http://host.docker.internal:11434`, в `.env` это `LLM_BASE_URL`.
- Модель держим загруженной в памяти (`keep_alive`), иначе каждое письмо начинается
  с 10–20 секунд загрузки.

## 11. Что реально повышает шанс на оффер

Автоотклики увеличивают число откликов, но приглашения дают точные отклики. Поэтому:

- лучше 40 откликов в день с подходящим резюме и письмом, чем 200 одинаковых;
- быстрый отклик в первые часы после публикации заметно повышает шанс, что резюме откроют, и
  часть 1 уже это даёт;
- `/stats` по ролям через 1–2 недели покажет, где приглашения, а где тишина; туда и смещаем
  объём.
